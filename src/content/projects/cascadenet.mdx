## Problem and constraints

<Confirm>Problem statement pulled from the project README. Check it matches the hackathon brief.</Confirm>

The project README frames the problem like this: in extreme weather, critical infrastructure fails not only from direct flooding but also through upstream dependencies. A flooded substation can disable water pumps, which can in turn paralyse hospitals.

The project was built for the disaster management track, over about six months by a team of about five. I worked on the ML side and the geospatial model.

The scope is Wayanad district, Kerala. The infrastructure data in the repo holds 25 nodes and 22 dependency edges across substations, water pumps, hospitals, roads and communication towers, plus 6 zones. Alerts target four agencies: Dam Safety, NDRF, the District Collector and the Highways department.

The data is mostly real, plus mock data, because raw live data was not available to us.

## Key decisions

What we built and why it fits the problem.

### 1. A physics-informed fallback behind the LSTM

`lstm_predictor_wayanad.py` falls back to a rules-based weighted scoring engine when TensorFlow is not installed, so the forecast endpoint keeps working without it. That fits a demo that has to run on machines we do not control.

### 2. Failure probabilities learned from a failure log, not hand-set

`dependency_graph.py` trains a Random Forest on `historical_failures_wayanad.csv` (distance, dependency type) to weight the edges of the NetworkX graph. That fits because the edge weights come from recorded failures rather than hand-set numbers.

### 3. A knapsack optimizer for the budget question

`roi_calculator.py` compares baseline and hardened cascade runs and selects which assets to protect with a 0/1 knapsack dynamic program under a budget cap. That fits the question agencies actually ask: which assets to protect for a fixed budget.

## MLOps specifics

What the repo shows:

- The FastAPI app in `AI_ML/src/api/main_wayanad.py` warms the cascade pipeline, the LSTM and the ROI ranking in background threads at startup.
- Responses are cached in memory with a 60-second TTL.
- Scenarios run in parallel with a `multiprocessing` pool.
- Endpoints cover simulation, what-if hardening (`/harden/{node_id}`), ROI ranking and allocation, flood grids by hour, zone predictions and alert triggering.

What the repo does not show: no Dockerfile, CI configuration or automated tests, and no experiment tracking or model registry.

## Limits

- The data is mostly real plus mock data, because raw live data was unavailable.
- When TensorFlow is missing, the fallback returns a hard-coded accuracy of 0.87 labelled as an empirical figure. It is not a measurement of this model.
- `main_wayanad.py` imports `src.models.lstm_predictor`, but the repo ships `lstm_predictor_wayanad.py`. The API may not start from a fresh clone without fixing that import.
